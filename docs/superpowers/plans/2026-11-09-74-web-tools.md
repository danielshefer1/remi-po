# #74 Let Remi Look Things Up on the Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remi answers "when does the pharmacy close", "what's the weather on Friday" and a pasted link in a private chat, using Anthropic's hosted web tools, and nothing a page says can get written.

**Architecture:** `AnthropicLLM` passes typed tools through untouched and reports the URLs of each turn's web results on `Completion`. `converse` resends a `pause_turn` with no extra message, capped. `respond` adds the two hosted tools, refuses direct writes once the turn has read the web, and lets a reply hold only a URL that came from a result this turn.

**Tech Stack:** Python 3.14, `anthropic` 1.8.0 (pinned, no new dependency), httpx2 `MockTransport` tests, pytest (`-m db`, `-m eval`).

**Spec:** GitHub issue #74 (`gh issue view 74`); run order in `docs/superpowers/plans/2026-11-03-free-remi-roadmap.md` (untracked, in the main checkout).

## Decisions

**Basic tool versions, `web_search_20250305` and `web_fetch_20250910`, on both models.** The issue's premise is out of date: Anthropic's docs now list `claude-haiku-5-5` for web search, web fetch and programmatic tool calling, so every version is open to it. The basic ones are still right, for a reason the issue didn't have:

| | Basic | `_20260209` and later |
|---|---|---|
| How it runs | Direct call | From inside code execution, by default |
| `max_uses` across a `pause_turn` | Earlier requests count | Searches run from code execution do **not** count from earlier requests |
| Extra to round-trip | Nothing | `code_execution` blocks, nested `caller` fields, a `container` id on every continuation |
| Benefit we'd lose | Fewer tokens on search-heavy turns; not worth it at 3 searches a turn | |

"Limited in code" (roadmap) needs `max_uses` to hold for the whole turn, so the direct versions win. They are documented for every model we'd use as `MODELS__CHAT_MODEL` or `MODELS__STRONG_MODEL`.

**No beta header.** The tool reference lists "None" for both. Both are on by default per organization, unless an admin turned them off in the Console, which comes back as a 400 and is the one thing the docs can't tell us. Task 1 proves it on CI. If an admin turns them off later, every agent turn falls back to the fixed "sorry" line; nothing here detects that.

**"Data, never instructions" goes in the prompt only.** The issue asks for it in the tool descriptions too, but a typed server tool has no description field: its `type`, `name` and settings are all there is.

**No web tools in a group.** The issue is silent. A group's history is other people's words sent as `user` messages, which web fetch treats as allowed URL sources, and the group turn has its own unconditional URL drop. Smallest safe choice: `GROUP_TOOLS` doesn't change, with a test pinning that.

**Nothing written after reading the web, in code.** Review Focus 2 ("a page tells Remi to do something: nothing gets written") can't rest on the prompt, because `set_reminder`, `cancel_reminder`, `remember`, `forget`, `set_briefing`, `set_timezone`, `live_calendar`, the sharing tools, `answer_outing` and `send_event_file` all act with no confirm. Once a turn has a web result, those tools return `_AFTER_WEB` and do nothing. `propose_event` and `propose_change` stay allowed because they only propose and the person must answer. The cost: "look up when it closes and remind me an hour before" takes one extra message ("It closes at 21:00. Want a reminder at 20:00?"). The gate reads the web sources before tools run, so a client tool called in the same step as a search, whose search the API hasn't run yet, is unaffected: no page has been read at that point.

**Which URL may appear in a reply.** A URL is allowed only if it is exactly, character for character, the `url` of a `web_search_result` or `web_fetch_result` from this turn. No normalising (not case, trailing slash, or query), because each is a way to launder. URLs inside page text never count, because only those two fields are read. A bare domain passes only as the exact host of such a URL, without `www.`, with no path. With no web result in the turn, today's `"http"` rule runs unchanged.

**`web_fetch` narrowed with `url_sources`.** Default URL sources include client tool results, so a stranger's invite title with a URL (through `list_events`) would be fetchable. `client_tool_results: none` stops that. `server_tool_results` is `only: web_search`, so a fetched page can't lead to the next page, only a search result can.

**An empty reply needs no new copy.** A search that fails returns an error block and the model continues; the prompt tells it to say so plainly. If it stays silent, the pause cap is hit, or a reply is dropped for a bad URL, `said` is `""` and `agent_turn` already sends `agent_unavailable` (`agent.py:1969`), a human line.

**Web turns get a longer timeout.** `AgentSettings.request_timeout_s` is 20 s and calls aren't streamed, so nothing arrives until the whole server loop ends: search, fetch and sampling. A request with a typed tool gets 60 s (`with_options`), which is what the strong model already gets. Every agent turn sends these tools, so every agent call can now wait 60 s for that turn; onboarding, confirm and group calls keep 20 s.

**No migration, no new dependency, no setting.** `0014` stays free. A web result is never stored: `load_history` holds only the sent text.

Checked offline against the pinned SDK 1.8.0 through the real `AnthropicLLM` over `MockTransport`: all three new block types and a citation parse, `to_dict()` works, and the assistant content goes back equal to what was received; a tool dict with `max_uses`, `url_sources` and `user_location` reaches the wire unchanged.

**What's in the code today that would break it:**
- `complete` builds each tool from `name`, `description`, `input_schema`: a typed tool raises `KeyError: 'description'`.
- `_wire` drops any trailing assistant turn as a prefill, and a `pause_turn` continuation is exactly that shape.
- `content` joins every text block, so narration before a search reads `"I'll check.Based on that, it closes at 9."`.
- `converse` reads a `pause_turn` as a finished turn.
- `llm.complete`'s Langfuse `input=wire` and `output` would carry the full page text.

Sentry and logs are already safe: `AnthropicIntegration` is off, `include_local_variables=False`, SDK errors aren't chained, and `llm.completed` logs only counts.

**Cost bound.** Normal web turn: one to three searches, 1 to 3 cents, plus tokens. In code: 3 searches and 2 fetches per run; a hand-off is a second run; a Hebrew redo is a new API turn with its own 3. A provider outage can repeat the job up to 7 times, so the absolute ceiling is about 84 searches, 84 cents. `max_content_tokens` caps text pages; PDFs aren't covered by it (docs), so a large one can push a prompt over Haiku's 100K price tier. Accepted for now.

```python
_WEB_BLOCKS: Final = frozenset(
    {"server_tool_use", "web_search_tool_result", "web_fetch_tool_result"}
)

def _final_text(content: Sequence[Any]) -> str:
    """The text after the last web block: before it is only narration."""
    last = max((i for i, block in enumerate(content) if block.type in _WEB_BLOCKS), default=-1)
    return "".join(block.text for block in content[last + 1:] if block.type == "text")
```

```python
_URL: Final = re.compile(r"https?://[^\s<>\"']+", re.IGNORECASE)
# Any letters before the dot, so a lookalike in another alphabet is still seen as a domain.
_BARE_DOMAIN: Final = re.compile(
    r"(?<![\w@.-])[\w-]+(?:\.[\w-]+)*\.(?:[a-z]{2,}|xn--[a-z0-9-]+)\b(?:/\S*)?", re.IGNORECASE
)
_URL_END: Final = ".,;:!?)]}'\"׳״"


def links_allowed(reply: str, sources: Collection[str]) -> bool:
    """Whether every link in ``reply`` is exactly a web result's URL from this turn, or the
    bare host of one. With no results, today's rule: no "http" at all."""
    if not sources:
        return "http" not in reply.lower()
    for match in _URL.finditer(reply):
        if match.group() not in sources and match.group().rstrip(_URL_END) not in sources:
            return False
    rest = _URL.sub(" ", reply)
    if "http" in rest.lower():
        return False
    hosts = {(urlsplit(u).hostname or "").removeprefix("www.") for u in sources}
    # shortcut: an all-non-Latin TLD (.рф) isn't seen as a domain, and "Node.js" reads as one and
    # drops that reply; list real TLDs if either shows up.
    return all(
        m.group().casefold().removeprefix("www.") in hosts for m in _BARE_DOMAIN.finditer(rest)
    )
```
