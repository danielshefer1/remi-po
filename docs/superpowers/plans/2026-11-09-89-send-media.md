# #89 Send Pictures and Files Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remi can send an image or a document in a private chat, at most once, and proves it by sending an `.ics` when someone says "send me that as a calendar file".

**Architecture:** An in-memory `Attachment` rides on `OutboundMessage` through `send_once` and the existing `send_text`, the way `poll_options` already does, so the `OutboundChannel` protocol and every fake stay as they are. Each adapter holds its own size and type limits and raises `AttachmentRefusedError` before any request. A new `send_event_file` agent tool builds the `.ics` from an event `list_events` showed in that turn and sends it inside the tool call, under its own outbox key `(inbox_id, "agent:file")`.

**Tech Stack:** Python 3.14, httpx multipart, `icalendar` 7.3 (already a dependency, unused until now), Postgres outbox, pytest (`-m db`, `-m eval`).

**Spec:** GitHub issue #89 (`gh issue view 89`); run order in `docs/superpowers/plans/2026-11-03-free-remi-roadmap.md` (untracked, in the main checkout).

## Decisions

**No migration, and the outbox row does not name the attachment.** The issue asks that a retried job rebuild the file. It already does: a job retry re-runs the whole `agent_turn`, so the model calls `list_events` and `send_event_file` again and the file is built afresh from the calendar. The row only has to say whether that send may still happen, and `(inbox_id, kind)` already says so. A column naming the attachment would need a resolver with no other caller, and would put an event reference in a table ADR 0003 keeps to delivery state. With no schema change, the "new code on the old schema" window doesn't apply here. `0014` stays free for the next issue that needs it.

| What the earlier attempt did | Row | What the retry does |
|---|---|---|
| Definitely not sent (`TransientChannelError`) | `pending` | Turn re-runs, file is rebuilt, sent once |
| File accepted, reply text failed | `accepted` | File is rebuilt, `send_once` returns `accepted` without sending; the reply goes out |
| Worker died mid-send | `sending` then `unknown` | Not sent; the "not sure it arrived" line |
| Timeout or 5xx after the request left | `unknown` | Not sent; the same line |
| Refused | `failed` | Not sent; the "couldn't send" line |

**The file goes first, inside the tool call.** `agent_turn` returns early once the reply text is claimed, so a file sent after the reply could never be retried. Sending in the tool also lets the model read what really happened.

**The fixed lines are code, not model wording.** A failed send appends a line from `onboarding_text` below the reply, as `connect_calendar` and the confirm question do. A model that wrongly says "sent" can't hide the failure.

**One event, one file, one per message, and only that date.** A repeating event's file holds only the listed date; the tool result tells the model to say so. A series written to someone's phone from a "next Sunday's class" request would be the worse mistake. `# shortcut: a repeating event's file holds only the date listed; add RRULE (UNTIL in UTC, RFC 5545) if someone asks for the series.`

**The caption has no event title.** It is built from the day and time only. Titles come from whoever sent the invite, and WhatsApp would make a domain in one tappable. The title appears only in the filename and inside the file.

**`ExportService` stays untouched.** `interfaces/exports.py` is an unimplemented protocol keyed on a tenant and a kind (Iterations 18 and 20). It doesn't fit one event, and nothing calls it.

**Two consequences:**

- **Meta can't take an `.ics`**, so that channel refuses it with the plain "can't send that kind of file" line. Passing it off as `text/plain` is undocumented, untested, and the channel is parked.
- **GOWA decides a document's type from its extension, not from what we send** (`usecase/send.go:749-762`). `.ics` is not in its own table (`src/pkg/utils/whatsapp.go:31-38`), so it falls to Go's `mime.TypeByExtension`, whose built-in table has `".ics": "text/calendar; charset=utf-8"` (`src/mime/type.go:86` at `go1.26.0`; the image builds on `golang:1.26-alpine3.23`). So the file needs a real `.ics` extension, which `event_file` always gives it. This comes from reading the source and has not been seen on a phone. Whether tapping it opens a calendar is what staging check 2 is for. If it doesn't, stop and ask (roadmap, "When to stop and ask"): nothing on our side can change the type GOWA reports.

## Global Constraints

- Every line a person reads follows "Product voice" in `CLAUDE.md`, equally natural in Hebrew and English. Fixed lines live in `messaging/onboarding_text.py`, the prompt in `messaging/agent.py`.
- File bytes and filenames never go in the outbox row, logs, Langfuse or Sentry. Sentry's `include_local_variables=False` (`observability/sentry.py:102`) already keeps locals out; do not change it. Tool results carry status only, since they reach Langfuse through `llm.complete`'s `input`.
- Remi only sends files it made or holds. `Attachment` has bytes and no URL field. The tool takes only `n`. No adapter ever sends `image_url`, `file_url` or `link`.
- Private chats only, enforced in code at the adapters and by the group turn having no such tool.
- No new dependency, no new setting, no migration. Scope excludes storing files (#88), reading incoming files (#87), group sends and web fetching.
- Run tests from the worktree with `PYTHONPATH=src`; its `.env` points at `po_t89`. Never print secret values.
- Gate per task: `uv run ruff check . && uv run ruff format --check . && uv run mypy src`, plus the task's tests.
- Live evals run only on CI, per Task 6.
- `graphify-out/` isn't in this worktree. Run `PYTHONHASHSEED=0 graphify update .` from the main checkout once this has merged.

## Review Focus

1. A job killed or retried around the file send: never two files, and the person is told if it may be lost. Tests in Task 1 and Task 5.
2. An event title or a message telling Remi to send or fetch something: nothing is fetched, and the file only ever goes to the sender. Tests in Task 5 and Task 6.
3. A hostile title reaching the file: path pieces, quotes, right-to-left overrides, or a newline forging a second event. Tests in Task 4.
4. A file too big or of a type the channel refuses: a plain line, no request made, no silent drop. Tests in Tasks 2, 3 and 5.
5. The file arrived but the model says nothing or writes a URL: the person must not get "sorry, I couldn't answer" after a delivered file. Test in Task 5.

import asyncio, struct, zlib, httpx
from personal_organizer.interfaces.channel import Attachment, OutboundMessage
from personal_organizer.providers.channel.gowa.outbound import GowaOutbound
from personal_organizer.settings import get_settings

def chunk(t, d): return struct.pack(">I", len(d)) + t + d + struct.pack(">I", zlib.crc32(t + d))
raw = b"".join(b"\0" + b"\x2a\x7f\xd4" * 256 for _ in range(256))
png = (b"\x89PNG\r\n\x1a\n" + chunk(b"IHDR", struct.pack(">IIBBBBB", 256, 256, 8, 2, 0, 0, 0))
       + chunk(b"IDAT", zlib.compress(raw)) + chunk(b"IEND", b""))

async def main():
    g = get_settings().gowa
    auth = httpx.BasicAuth(g.basic_auth_user, g.basic_auth_password.get_secret_value())
    async with httpx.AsyncClient(base_url=f"{g.base_url}/", auth=auth, timeout=15.0) as http:
        print(await GowaOutbound.from_settings(g, http).send_text(OutboundMessage(
            "<the user's phone, E.164>", "בדיקה: תמונה מרמי",
            attachment=Attachment(png, "test.png", "image/png"))))

asyncio.run(main())
